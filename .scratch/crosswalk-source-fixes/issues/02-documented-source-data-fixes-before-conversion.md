# A function that documents known crosswalk bugs and fixes them before conversion

Status: ready-for-agent
Category: enhancement

Raised by the maintainer after the miscoded district row (shares-from-counts
issue 02): as a general rule, known bugs in the BBSR files should be documented
in one place and fixed before the conversion, instead of being absorbed by
renormalization.

## Observation

Known source-data bugs so far (all in the downloads of 2026-10-24; each is an
observation from the issues named, not a fix):

- District 2011 -> 2012: a row with `name_old` Bernkastel-Wittlich is coded
  `ags_old` 07235000; it belongs to 07231000 (shares-from-counts issue 02).
- District 2014 and 2015: single-row groups of 07135000 and 07137000 repeat the
  2013 share values (0.962 / 0.038); cause not established (municipal issue 06).
- Municipal 1990-2000: four units (12039430, 12043470, 15321210, 01060102)
  with a share of 1 on every row; handled by the counts rule in
  `renormalize_forward_shares()` (municipal issues 05 and 06).

Today these are handled by renormalization (`renormalize = TRUE`), which keeps
totals but, for the miscoded row, passes 0.86 % of one district's value on to
the wrong unit. `data-raw/popregio.R` already documents and applies recodes for
the GENESIS-Regio series (Aachen, Hannover, Eisenach), but only in the dataset
build, not for crosswalks.

## To establish

1. Form: a table of fixes shipped with the package (like the URL table in
   `R/sysdata.rda`) with, per row, file/level, transition, the affected
   `ags_old`/`ags_new`, the replacement, and the evidence; and an exported
   function that applies it to a crosswalk and reports what it changed.
2. When it runs: inside `bbsr_crosswalk_read()` by default, or as a separate
   step the user calls before `harmonize_regions()`; and how a user switches it
   off.
3. Which known bugs qualify: only those with a verified correct value (the
   Bernkastel-Wittlich row: yes; the 2014 and 2015 district rows: cause not
   established, so probably not). Whether the counts-rule cases stay in
   `renormalize_forward_shares()`.
4. How a fix survives a changed upstream file: a fix should check that the
   row it targets is still as described and say so if not.
5. Whether this deserves an ADR (it changes converted numbers).

## Out of scope

Detecting new bugs (issue 01, shares-from-counts issue 02). Contacting BBSR;
see `ltc-validation` issue 08.

## Comments

> *This was generated by AI during triage.*

Decisions (maintainer):

- The fix logic is a separate, exported function, `bbsr_crosswalk_fix()`;
  `bbsr_crosswalk_read()` calls it by default and takes `fix = FALSE` to return
  the file as published.
- The fixes are an R table in the package source (not `sysdata.rda`).
- Only fixes with a verified correct value are included: today the
  Bernkastel-Wittlich row. The 2014 and 2015 district rows stay on
  renormalization; the 1990-2000 units stay on the counts rule.

Triage verification (district file, download of 2026-10-24): matching the row
by `ags_old` 07235000, `year_from` 2011 and `name_old` "Bernkastel-Wittlich"
selects exactly one row. Recoding its `ags_old` to 07231000 makes both groups
sum to 1 (07231000: area 1, population 1; 07235000: area 1, population 1),
which is the evidence that the recode is right (shares-from-counts issue 02).
Item 5 (ADR): not needed; the table with its evidence per row is the record,
and ADR 0001 is unaffected.

## Agent Brief

**Category:** enhancement
**Summary:** An exported `bbsr_crosswalk_fix()` applies a table of documented, verified corrections to a crosswalk read from the BBSR files, and `bbsr_crosswalk_read()` applies it by default.

**Current behavior:**
`bbsr_crosswalk_read()` returns the files as published. The miscoded district row (`ags_old` 07235000, `name_old` Bernkastel-Wittlich, 2011 -> 2012) leaves 07231000 at a share sum of 0.991 and 07235000 at 1.009; `harmonize_regions()` rescales both, so 0.86 % of Bernkastel-Wittlich's value stays with it instead of going to Trier-Saarburg.

**Desired behavior:**
- A table in `R/crosswalk-fixes.R`, one row per fix, with: `level`, `year_from`, `year_to`, the matching columns (`ags_old`, `name_old`, `ags_new`), the column to change and its new value, and an `evidence` string (what was observed and where, as in the triage comment). First and only row: the Bernkastel-Wittlich row, `ags_old` 07235000 -> 07231000.
- `bbsr_crosswalk_fix(crosswalk)`: applies each fix to the rows that match all its matching columns. A fix applies only when exactly one row matches. It returns the crosswalk and one `rlang::inform()` naming each applied fix (transition, codes, evidence). A fix whose transition is in the crosswalk but whose row is not found, or matches more than one row, is not applied and is named in the same message as "not applied: the file may have changed".
- `bbsr_crosswalk_read()` gets `fix = TRUE` and calls `bbsr_crosswalk_fix()` after reading and before `bbsrgeo_check_share_sums()`, so the share-sum check sees the corrected rows. `fix = FALSE` returns the file as published.
- Roxygen for `bbsr_crosswalk_fix()` (and `bbsr_crosswalk_read()`'s `fix`) documents that the fixes change the data and where the list is kept; a `GLOSSARY.md` entry for **Source-data fix** if the term is used.

**Acceptance criteria:**
- [ ] Tests on small constructed tibbles: a fix applies to its one matching row (value changed, other rows untouched, message names it); no matching row but the transition present gives "not applied"; two matching rows give "not applied"; a crosswalk without the transition gives no message; `fix = FALSE` leaves the data unchanged.
- [ ] Real-file test in `test-crosswalk-read.R` (network-guarded): the district file read with the default has `ags_old` 07231000 and 07235000 in 2011 -> 2012 summing to 1 (area and population, within 1e-3), exactly one fix message, and no share-sum warning from them; with `fix = FALSE` the row is as published.
- [ ] `harmonize_regions()` on that crosswalk moves 0.86 % of 07231000's value to 07235000 (constructed data), where before the change it did not.
- [ ] All existing tests pass; municipal files read with no fix message.

**Out of scope:**
- The 2014 and 2015 district rows and the 1990-2000 units (they stay on renormalization and the counts rule).
- Detecting new bugs: `name_old` check (issue 01) and shares-vs-counts check (shares-from-counts issue 02).
- Contacting BBSR.
