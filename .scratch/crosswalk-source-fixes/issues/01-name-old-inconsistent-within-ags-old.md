# Report ags_old groups whose name_old is not constant

Status: done
Category: enhancement

Raised while triaging shares-from-counts issue 02: the miscoded row
07235000 (2011 -> 2012, `name_old` Bernkastel-Wittlich, which is 07231000) was
found by the maintainer by reading the sheets. Its `name_old` disagrees with
the other rows of the same `ags_old`.

## Observation

In every cached file (downloads of 2026-10-24) the rows of one
`ags_old`/`year_from`/`year_to` group were checked for more than one distinct
`name_old`:

| File | Groups | Groups with more than one `name_old` |
| --- | --- | --- |
| municipal 1990-2000 | 151002 | 0 |
| municipal 2000-2010 | 127333 | 0 |
| municipal 2010-2020 | 112120 | 0 |
| municipal 2020-2024 | 54919 | 0 |
| districts | 14743 | 1 (07235000, 2011 -> 2012) |

So on these files the check has no false positives and finds the known case.
It would not find a miscoded row that is the only row of its group, nor a
miscoded `ags_new` (not checked here), nor a code coded consistently wrong.

## Out of scope

## Agent Brief

**Category:** enhancement
**Summary:** `bbsr_crosswalk_read()` warns, after applying the fixes of issue 02, about `ags_old` (and `ags_new`) groups whose names are not constant, naming the codes and names.

**Current behavior:**
A row whose `ags_old` does not belong to its `name_old` (07235000 with `name_old` Bernkastel-Wittlich, 2011 -> 2012) is not detected; it shows only through the share sums.

**Desired behavior:**
- A check `bbsrgeo_check_names()` (internal, like `bbsrgeo_check_share_sums()`), called from `bbsr_crosswalk_read()` after `bbsr_crosswalk_fix()` (issue 02) and before `bbsrgeo_check_share_sums()`. If issue 02 is not implemented yet, call it after reading.
- For each `ags_old`/`year_from`/`year_to` group, more than one distinct non-`NA` `name_old` is reported; the same for `ags_new`/`year_from`/`year_to` and `name_new`. `NA` names are ignored.
- One `rlang::warn()` per read: the number of groups per side, and up to five examples with the codes, transition and the names found (e.g. `ags_old` 07235000, 2011 -> 2012: "Bernkastel-Wittlich", "Trier-Saarburg"). It states no cause beyond "the names of one code differ", and says to check the original file.

**Acceptance criteria:**
- [ ] Tests on small constructed tibbles: consistent names (no warning), two names under one `ags_old` (warning with both names and the transition), the same under `ags_new`, `NA` names ignored (including a group of `NA` plus one name), and a crosswalk without name columns does not error.
- [ ] Real-file test in `test-crosswalk-read.R`: with `fix = FALSE` (or before issue 02 is implemented) the district file warns about exactly 07235000 (2011 -> 2012); the municipal files do not warn. With issue 02 implemented and `fix = TRUE`, no name warning.
- [ ] `harmonize_regions()` output unchanged; all existing tests pass.

**Out of scope:**
- Correcting the data (issue 02) and deriving the right code from the name.
- Comparing names across transitions (a unit can be legitimately renamed).
- Checking shares against counts (shares-from-counts issue 02).


## Resolution

`bbsrgeo_check_names()` in `R/crosswalk-read.R`, called by
`bbsr_crosswalk_read()` after `bbsr_crosswalk_fix()` and before
`bbsrgeo_check_share_sums()`. With `fix = FALSE` the district file warns about
07235000 (2011 -> 2012); with the default fix, and for the municipal files, no
name warning (the real-file tests in `test-crosswalk-read.R`).
