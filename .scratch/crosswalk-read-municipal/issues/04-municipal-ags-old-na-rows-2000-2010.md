# Municipal files 1990-2020: second header row read as a data row (ags_old = NA)

Status: done
Category: bug

Follow-up from issue 01 (municipal crosswalk reading, commit 1f98881). Found
by reading the cached municipal files and checking share sums. Originally
filed for the 2000-2010 file only; triage showed it affects three files.

## Observation

Reading `ref-gemeinden-2000-2010.xlsx` reports 10 `ags_old`/`year_from` combinations off 1 by area share, including `ags_old = NA`, `year_from = 2000` (sum 0). The NA rows are not data: the sheets have a two-row header (row 1 the title, e.g. "Gemeinden, Stand 31.12.2000"; row 2 the column labels "Kennziffer", "Name", "flächenprop.", "km²", ...), and `bbsrgeo_read_sheet()` drops only row 1, so row 2 comes through with `ags_old` = `ags_new` = NA, `name_old` = `name_new` = "Name" and all shares and counts NA.

## Resolution

`bbsrgeo_read_sheet()` drops rows whose first cell is "Kennziffer" (the second
header row) right after removing row 1, before AGS normalization. Detected by
content because sheets 2016-2017 to 2019-2020 of the 2010-2020 file and all
later sheets have only one header row; checked on every sheet of the five
downloaded files (row 2, column 1 is "Kennziffer" on exactly the 10 + 10 + 6
sheets listed below).

Real files after the fix: no NA `ags_old`/`ags_new` in any of the five; row
counts 151093 (1990-2000), 127337 (2000-2010, was 127347), 112275 (2010-2020),
54949 (2020-2024), 14908 (districts). Reading the 2000-2010 file no longer
warns. The 1990-2000, 2010-2020 and district files still warn about
non-NA share deviations (4, 1 and 4 combinations); those are not this issue.

Tests: fixture `ref-gemeinden-testfixture-kopfzeilen.xlsx` (one sheet with and
one without the second header row) and two network-guarded tests in
`test-crosswalk-read.R`.

## Agent Brief

**Category:** bug
**Summary:** `bbsr_crosswalk_read()` must not return the second header row of municipal sheets as a data row.

**Current behavior:**
For municipal annual sheets that have a second header row (column labels such
as "Kennziffer" / "Name" below the title row), the reader returns it as a
crosswalk row with NA `ags_old` and `ags_new`, `name_old` = `name_new` =
"Name" and NA shares and counts. 10 such rows in the 1990-2000 file, 10 in
2000-2010 and 6 in 2010-2020. They form an `ags_old = NA` group with share
sum 0, so the share-sum check warns about it.

**Desired behavior:**
The reader drops header rows, detected by content (an `ags_old` cell that is
the label "Kennziffer", or equivalent), so that sheets with and without the
second header row both read correctly. No other row is dropped. The
Regionalschluessel layout and the district file keep reading as before.

**Key interfaces:**
- `bbsr_crosswalk_read()` output: no row with NA `ags_old` or NA `ags_new`.
- The share-sum check (`bbsrgeo_check_share_sums()`): no longer reports an
  `ags_old = NA` group for these files.
- Do not rely on `normalize_ags()` turning "Kennziffer" into NA as the
  mechanism; drop the row explicitly before AGS values are normalized.

**Acceptance criteria:**
- [ ] For each of the five cached crosswalk files, the read result has no row with NA `ags_old` or NA `ags_new`.
- [ ] Row counts drop by exactly 10, 10 and 6 for the 1990-2000, 2000-2010 and 2010-2020 files; the 2020-2024 and district results are unchanged.
- [ ] Reading the 2000-2010 file no longer produces a share-sum warning mentioning `ags_old = 'NA'`.
- [ ] A test covers one sheet with the second header row (e.g. 2000-2001) and one without (e.g. a 2016-2019 sheet of the 2010-2020 file), asserting the first data row is the first municipality (e.g. Flensburg, `01001000`, for 2000-2001).
- [ ] Tests that need the network or cached files follow the existing `skip_on_cran()` / `skip_if_offline()` pattern.

**Out of scope:**
- Changing the share-sum warning wording.
- Correcting BBSR data itself.
- The 444-code share sums above 1 (issue 05, done).
