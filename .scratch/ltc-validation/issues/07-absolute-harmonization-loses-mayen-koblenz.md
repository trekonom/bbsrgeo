# harmonize_regions(type = "absolute") collapses Mayen-Koblenz counts to ~0

Status: done (uncommitted)
Category: bug

Found while re-running the ltc-validation check on harmonized output (issue 02 grilling). Not yet investigated beyond the observation below.

## Observation

Harmonizing `ltcregio` with `type = "absolute"` (`value_cols = c("pflegebeduerftige", "population_total")`, `weight = "population"`, `target_year = "current"`, `level = "districts"`, annual crosswalk) gives AGS 07137000 (Mayen-Koblenz) a harmonized `population_total` of about 0.03% of `popinkar` for 2009, 2011 and 2013 (ratio 0.000294), and 1.7% for 2015 (ratio 0.017151). All other districts match `popinkar` within about 0.4% for those years, apart from the Cochem-Zell (07135000) anomaly below.

The BBSR annual crosswalk has a known share-sum anomaly for 07135000 and 07137000, 2014->2015 and 2015->2016: `share_population` is 0.983 / 0.017 instead of 1.0 / 0.0 (see `tests/testthat/test-validate-ltc.R`, `bbsrgeo_check_share_sums()`, and the warning `harmonize_regions()` emits about 4 `ags_old`/`year_from` combinations). Likely mechanism (unverified): chaining multiplies the anomalous shares, so almost all of Mayen-Koblenz's absolute count is assigned elsewhere or dropped.

Cochem-Zell (07135000) is also off under `type = "absolute"`: harmonized population is 0.969 of `popinkar` for 2009-2013.

`type = "ratio"` is not visibly affected: rate deviation vs INKAR for 07137000 is below 0.14% in every year, because the weights are normalized.

## Why it matters

- `type = "absolute"` silently returns a wrong value (about 0.03% of the true count) for a whole district, with only a generic share-sum warning. The sum of absolute values across Germany is therefore also off.
- The popregio/popinkar validation (`tests/testthat/test-validate-inkar.R`) may hide this through its exclusion list; check before relying on it.

## To establish

1. Reproduce for `popregio` (`type = "absolute"`) and confirm which transition(s) in the chain lose the count.
2. Decide the intended behaviour: renormalize shares per `ags_old`/`year_from` when the sum deviates from 1, error or warn per affected district, or leave as is and document it.
3. Check whether `harmonize_regions_municipalities()` has the same exposure.

Related: issue 02 (test exclusion for the same districts), issue 05 (exclusion list scope).

## Agent Brief

**Category:** bug
**Summary:** `harmonize_regions(type = "absolute")` silently loses most of a district's count when the crosswalk's shares for an `ags_old` do not sum to 1; renormalize and warn.

**Current behavior:**
In `type = "absolute"`, each transition multiplies values by `share_<weight>` and sums per target AGS, with no check that the shares of one source AGS add up to 1. BBSR's annual districts crosswalk has transitions where they do not (07135000 and 07137000, 2014->2015 and 2015->2016: 0.983 / 0.017 for a district that maps unchanged to itself). Chaining multiplies these, so Mayen-Koblenz's harmonized count is about 0.03% of the true value for years up to 2014, with only the generic share-sum warning. The same code path serves the municipality level.

**Desired behavior:**
- For `type = "absolute"`, in each forward step, shares are renormalized per source AGS (`ags_old`) so they sum to 1 when their sum deviates from 1 by more than the tolerance already used by the package's share-sum check (currently 0.01). Deviations within tolerance are left untouched.
- For a self-mapping district like Mayen-Koblenz this restores the full count; for a split district the proportions between the targets are preserved.
- When renormalization happens, `harmonize_regions()` emits a warning naming the affected AGS values and the transition(s). It must be clear from the message that the crosswalk, not the user's data, is the cause.
- `type = "ratio"` results are unchanged.
- Backcasting (`allow_backcast = TRUE`) is out of the renormalization rule, since shares there are not expected to sum to 1 per `ags_new`. Behavior is unchanged; confirm this explicitly and note it in the roxygen docs.
- Same behavior at the municipality and district levels (both share the step logic). Check against the municipal crosswalk and report whether any municipal transitions are affected.

**Key interfaces:**
- `harmonize_regions()` (and the district/municipality variants it dispatches to): behavior for `type = "absolute"`; no new arguments.
- The step function that applies one crosswalk transition: where the renormalization belongs.
- Roxygen docs of `harmonize_regions()`: document the renormalization and the warning; re-roxygenise, do not hand-edit `man/`.
- `tests/testthat/test-validate-inkar.R` and `tests/testthat/test-validate-ltc.R`: the share-sum exclusion of affected districts should be removed from the absolute (population) comparison, if the renormalization makes them pass at the existing tolerance. Per the project's root-cause-over-tolerance rule, do not loosen tolerances; investigate any remaining outliers instead. Keep the exclusion for the ltc ratio test only if still needed (see issues 02 and 05).

**Acceptance criteria:**
- [ ] A unit test with a small synthetic crosswalk (self-mapping AGS with shares summing to e.g. 0.017, chained over two transitions) shows the harmonized absolute count equals the input count.
- [ ] A synthetic split case (one source, two targets, shares summing to 0.9) distributes the full count proportionally.
- [ ] Shares within tolerance of 1 give results identical to the current implementation.
- [ ] A warning naming the affected AGS is emitted when renormalization occurs, and none otherwise (test with `expect_warning` / `expect_no_warning`).
- [ ] `type = "ratio"` output is identical to before on a fixed example.
- [ ] With the real crosswalk, harmonized `popregio` for 07137000 and 07135000 matches `popinkar` at the same tolerance as the other districts, for 2009-2015 and for 1995-2008.
- [ ] The population validation test no longer excludes these districts (or the issue states which remain excluded and why).
- [ ] `Rscript dev/test-all.R` passes with no new skips.

**Out of scope:**
- The 54 district-years in 10 other districts that deviate more than 1% from INKAR (separate investigation).
- Changing how `bbsr_crosswalk_read()` warns about share sums or correcting the crosswalk data itself.
- Backcasting behavior.
- The ltc rate validation tolerances and the Rhein-Hunsrück residual (issues 02, 05).

## Resolution

Root cause (confirmed): `harmonize_step()` multiplied values by the crosswalk shares as given; a self-mapping row with share 0.017, chained over 2014->2015 and 2015->2016, left 0.017^2 of the count. Reproduced by `dev/scratch/repro-07-synthetic.R` (1000 -> 0.289) and `dev/scratch/repro-07-real.R` (42 bad district-years for 07135/07137; both scripts are gitignored scratch).

Fix: `renormalize_forward_shares()` in `R/harmonize-regions.R`, called once per `harmonize_regions()` call for `type = "absolute"`. It renormalizes `share_<weight>` per `ags_old`/`year_from`/`year_to` when the sum deviates by more than `SHARE_SUM_TOLERANCE` (0.01, now shared with `bbsrgeo_check_share_sums()`), and warns once naming the AGS and transitions. Backcasting uses the original shares; `type = "ratio"` is untouched. Roxygen documents this.

After the fix, real data: 07137 ratio to `popinkar` is 1.000 in all years; 07135 is 1.003 for 1995-2013 and 1.000 from 2014. `test-validate-inkar.R` no longer excludes affected districts. `Rscript dev/test-all.R`: 94 pass, 0 skips, 1 warning (the pre-existing share-sum warning from `bbsr_crosswalk_read()`, also present before the change).

`test-validate-ltc.R` still has its exclusion; it covers the ratio test (issues 02 and 05).

Municipal level: not verified. `bbsr_crosswalk_read()` aborts on the municipal annual file (`ref-gemeinden-1990-2000.xlsx`: "Unexpected sheet name '1990-91'"), so the share sums could not be checked. The step logic is shared, so the same renormalization applies. Reading that file is a separate issue.
