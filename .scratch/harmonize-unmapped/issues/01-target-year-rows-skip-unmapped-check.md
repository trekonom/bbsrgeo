# Rows already at the target year bypass the unmapped-unit check

Status: done
Category: bug

Found while grilling the domain model (GLOSSARY.md).

## Observation

`harmonize_path()` returns rows with `start_year == target_year` unchanged, before any crosswalk lookup. An AGS in `data` that the crosswalk does not know is therefore dropped (with a warning) in earlier years, but kept silently in the target year.

## Intended behaviour

Every row should face the same unmapped-unit rule: an AGS with no crosswalk entry is dropped with a warning, never passed through. Decide what "has a crosswalk entry" means for target-year rows (e.g. present as `ags_new` in the last transition into the target year).

## To establish

1. Reproduce with a target-year row whose AGS is absent from the crosswalk.
2. Decide the lookup rule for target-year rows.
3. Check whether `check_regions()` already reports these.

## Triage notes

Confirmed by reading the code, not yet reproduced: `harmonize_path()` (`R/harmonize-regions.R`) returns `group` unchanged when `start_year == target_year`, before any crosswalk lookup. `check_regions()` does not catch these rows either: it treats an AGS as known if it occurs as `ags_old` or `ags_new` in any year, so a unit that is unknown for the target year but known elsewhere passes.

## Agent Brief

**Category:** bug
**Summary:** Rows already at `target_year` must face the same unmapped-unit rule as every other row (see GLOSSARY.md, "Unmapped unit"): dropped with a warning, never passed through.

**Decided lookup rule:** a target-year row is mapped if its AGS occurs as `ags_new` in the crosswalk for any transition into `target_year` (`year_to == target_year`). For crosswalks with several `year_to` values (annual), this means the last transition into the target year; for `conversion_*` crosswalks, the single fixed `year_to`. Do not require `ags_old` presence at `target_year`. If the crosswalk has no transition into `target_year` at all (e.g. `target_year` is the earliest year, or only backcasting applies), do not drop anything and do not warn.

**Required changes:**
1. In `harmonize_path()` (or the caller), apply the lookup rule above to rows with `start_year == target_year`: drop unmapped rows and emit the same warning as the existing unmapped-unit path (reuse its wording/helper; do not write a second message).
2. Add a failing-first test in `tests/testthat/test-harmonize-regions.R`: a panel containing a target-year row with an AGS absent from the crosswalk. Assert it is dropped and warned about, matching the behaviour for the same AGS in an earlier year. Add a control that a mapped target-year row passes through unchanged.
3. Update the roxygen docs of `harmonize_regions()` if they state or imply pass-through, then `Rscript dev/document.R`.

**Out of scope:** changing `check_regions()` (separate decision; mention in the PR that it still accepts such an AGS if it is known in any year).
